# Claude Code hooks

Wired in `.claude/settings.json`; each runs as `python3 .../<hook>.py`, with a 120 s timeout (10 s for `scope.py` and `touched.py`). Lint, format, type-check and import-contract rules live in [tests/docs/testing.md](../../tests/docs/testing.md).

| File | Event | Blocks? | What it does |
|---|---|---|---|
| `hooklib.py` | — | — | Shared plumbing, stdlib only: stdin payload, `stop_hook_active` guard, caller, written path and its tree, touched-files record, git, status line, loop breaker. |
| `scope.py` | PreToolUse (`Edit\|Write\|NotebookEdit`) | Yes (deny) | Denies a file write outside the calling agent's scope in `.claude/ownership.json`, with a reason naming the agent, the path and the agents whose scope covers it. Silent when it allows. |
| `touched.py` | PostToolUse (`Edit\|Write\|NotebookEdit`) | No | Appends the written path to the caller's touched-files record. Silent, never blocks. |
| `lint.py` | Stop, SubagentStop | Yes (exit 2) | Applies `ruff format` and import sorting (`ruff check --select I --fix`) to the `.py` files the stopping agent wrote, then runs `ruff check` on them. Status `format ✓ (N files) · lint ✓ (N files)`, or `format - · lint -` when it wrote none. |
| `typecheck.py` | Stop, SubagentStop | Yes (exit 2) | Runs `basedpyright` on the `.py` files the stopping agent wrote under `dispatcher/`, `skills/` and `tests/`, and `lint-imports` on the whole project, in parallel. Status `types ✓ (N files) · imports ✓`, or `types -` when it wrote none. |

On a Stop block the failing tool's output goes to stderr, which Claude reads, and the turn continues. A `scope.py` deny prints the PreToolUse JSON form (`hookSpecificOutput.permissionDecision: "deny"` with a `permissionDecisionReason`) and exits 0; Claude sees the reason instead of the tool result.

Tests: `.claude/hooks/tests/test_hooks.py` covers `scope.py` allow/deny, `touched.py` recording, the Stop hooks' `stop_hook_active` exit, and the ownership map (every path exists, except `**/` patterns; every mapped agent has an agent file; every doc linked from the tables in [docs/README.md](../../docs/README.md) is writable by at least one agent or listed under `main`, never both); run `uv run pytest .claude/hooks/tests -q`. The lint and type-check runs themselves are not tested.

The type check needs the optional extras installed (`uv sync --extra robot --extra vision`); without them the robot and vision imports in `skills/real.py` are unresolved and touching that file blocks.

## Why they are built this way

- **Files the stopping agent wrote only.** `touched.py` appends each Edit/Write/NotebookEdit target (absolute, `realpath`) to `${TMPDIR:-/tmp}/claude-touched-<session_id>-<caller>`, where the caller is the payload `agent_id`, or `main` for the main session, whose payloads carry no `agent_id` (both ids reduced to `[A-Za-z0-9_-]`). A path outside this project's checkout and its worktrees is not recorded. On SubagentStop the checks read that agent's record, on Stop the main session's, keeping existing `.py` files only, so an agent is never blocked by another session's or agent's uncommitted work. No baseline file is needed, because the commit rule `uv run ruff format .` keeps committed files clean. The whole-repo checks stay the pre-commit commands. A touched file that already had errors does block; the loop breaker lets the second stop through.
- **Record cleared per hook on a pass.** Each Stop hook keeps its own position in the record (`claude-<hook>-checked-<session_id>-<caller>`, a character offset) and advances it to the end only when all its checks pass; a block, or a repeat let through by the loop breaker, keeps it, so the failing files are checked again at the next stop. A file written again later is appended again and rechecked. Two positions instead of one shared clear, because `lint.py` and `typecheck.py` run in parallel on the same record.
- **Each touched file checked in its own tree.** A recorded path is resolved to the git top level of its own location (as `scope.py` does), and the tools run there, one run per tree, so a file in a worktree (`<repo-root>-<slug>`) is checked against that worktree's config and environment, never `$CLAUDE_PROJECT_DIR`. With files in more than one tree, the failure output names the tree.
- **Type check limited to the `[tool.basedpyright]` `include` roots** (`dispatcher/`, `skills/`, `tests/`, listed in `typecheck.py`). File arguments bypass `include`, so without the filter a root-level script would be checked although the config leaves it out. `lint-imports` is whole-project and fast, so it runs in each tree that has a touched `.py` file.
- **Format never blocks, and runs inside `lint.py`, before the lint.** Hooks on one event run in parallel; a separate format hook would race the lint on the same files, and the `W`, `E501` and `I` rules would fail falsely on unformatted code. The format status is merged into the lint line.
- **`typecheck.py` runs in parallel with `lint.py` safely.** It never writes files, and formatting never changes types.
- **One JSON object on stdout.** `report()` prints `{"systemMessage": ..., "suppressOutput": true}`, the only line the user sees, so every hook reports even when idle (`lint -`, `types -`). A hook must print at most one object.
- **Loop breaker.** With `stop_hook_active` true a hook exits 0 at once. In addition, `block()` stores an md5 of the failure output in `${TMPDIR:-/tmp}/claude-<hook>-<session_id>-<caller>`, per caller so two agents never share a digest; the same failure a second time reports `<hook> ✗ unchanged since the last block; not blocking again (run <command>)` and exits 0. A clean run deletes the file.
- **Session tree from the payload `cwd`** (fallback `git rev-parse --show-toplevel`; exit 0 outside a repo), never `$CLAUDE_PROJECT_DIR`. Its `--git-common-dir` decides which paths belong to this project for `scope.py` and `touched.py`.
- **Scope from the ownership map, keyed by `agent_type`.** `.claude/ownership.json` is the single source for which project agent may write which paths; `scope.py` reads it from its own checkout (`.claude/` next to `hooks/`), so a worktree uses its own copy. Shape: `agents` maps each project agent's name (the agent file's `name:`) to a list of repo-relative paths; `packages` lists the paths denied to the main session and to agents without an entry; `main` lists the docs only the main session writes. Path syntax: a trailing `/` is a folder, `**/name` that file name at any depth (`tests-dev`'s `**/conftest.py`, for "any `conftest.py`"), anything else one file. A subagent's payload carries `agent_id` and `agent_type`; the main session's carries neither. `reviewer` has an empty list. The main session and any agent without a list (built-ins such as `general-purpose`, `Explore`, `Plan`) are denied only `packages` (`dispatcher/`, `skills/`), so the main session cannot route a package edit through a built-in agent. A missing or malformed map allows every write, like any other bad input; the hook tests catch a broken map. The agent files' Scope sections and the `delegate` skill link the map instead of listing paths; they keep only the rules a path list cannot express (cross-service use of `tests/integration/`, the `pyproject.toml` sections `tests-dev` may touch, `claude-config-dev`'s ban on the git-ignored `.claude/settings.local.json` inside its `.claude/` entry).
- **`main`: docs owned by the main session.** `docs/README.md`, `docs/project.md`, `docs/architecture.md` and `docs/references.md` (project-level, cross-cutting) belong to the main session, not to a subagent. No agent's list may cover a `main` path, and the hook does not deny the main session there (only `packages` are denied to it).
- **Written-path resolution** (`scope.py`, `touched.py`, shared in `hooklib.py`). `file_path` (or `notebook_path`) is resolved against the payload `cwd` and `realpath`, then made relative to the git top level of the file's own location, so a worktree is checked like the main checkout. A path outside any git tree, or in a repo with a different `--git-common-dir` from the session's tree (a scratch repo), is always allowed by `scope.py` and never recorded by `touched.py`. Bad or empty payloads (including a `tool_input` that is not an object) are allowed: the hook is a guard rail, not the safety boundary.
- **System `python3`, tools through `uv run`.** The hooks are stdlib only, so they skip the venv start-up; ruff, basedpyright and lint-imports still run from the project environment.

## Design decisions

- **Agent scope enforced by a PreToolUse hook with per-agent allow-lists.** The Scope sections and the CLAUDE.md working pattern were prose only; the hook makes them hard for file-edit tools. Ambiguous Scope wording is read the way the ownership table in [docs/README.md](../../docs/README.md) reads: root `tests/` "where the task is cross-service" is `tests/integration/` only; "shared docs, notably ..." is the named files only; `tests-dev` gets `dispatcher/tests/` and `skills/tests/`, since its Scope allows brief-named mechanical edits there that the hook cannot tell apart. Known gap, accepted: writes through Bash (`sed -i`, heredocs, redirects) are not checked. Rejected: `Edit(...)`/`Write(...)` deny rules in `settings.json`, which apply to every session and subagent alike and cannot tell agents apart.
- **One ownership map, JSON, with prose that links it and a test that checks it** (user decision). The agent-to-path mapping was hand-written in `scope.py`, each agent's Scope section, the `delegate` skill and `docs/README.md`, kept in step by an unchecked rule. JSON because the hooks run on system `python3` 3.10, which has no `tomllib`, and stay stdlib only. The prose copies are trimmed to a link, and the hook tests check the map against the repo, the agent files and the `docs/README.md` tables. Rejected: a generator rewriting marked blocks in the prose files, more machinery than the drift it prevents; cross-checking five unchanged copies, which keeps the duplication and only detects it.
- **`claude-config-dev` may write `.claude/ownership.json`** (user decision). The map lives at `.claude/` because it feeds the agents and the `delegate` skill, not only the hooks, and its maintainer is the agent that owns `.claude/`.
- **Fixed-text edits ask, through plain `ask` rules in `settings.json`, not a hook** (user decision). `Edit` and `Write` on `dispatcher/prompts.py` and `skills/catalog/**/SKILL.md` prompt the user, since those texts change the registry hash and golden files ([skills/docs/skills.md](../../skills/docs/skills.md)). The rules use absolute `//**/` patterns so they also match a `<repo-root>-<slug>` worktree edited from a session rooted in the main checkout; the catalog path keeps `.claude/skills/*/SKILL.md` out. They combine with `scope.py`: its deny still wins, and its allow is silent, so the ask still prompts. Known gap, accepted: Bash writes are not covered. Rejected: a PreToolUse hook, unneeded when settings rules suffice. Only `Edit(path)` rules are listed: Claude Code matches file permission checks against `Edit(path)` rules, which cover all file-editing tools including `Write`; `Write(path)` rules are never matched and draw a start-up warning.
- **Python over bash, on one shared module.** The payload parsing, caller, written-path and tree lookup, touched-files record, status line and loop breaker live once in `hooklib.py` instead of being copied into each hook. Rejected: bash scripts with inline `python3 -c` snippets for the JSON handling, which duplicated that plumbing in every hook and needed a second language for it anyway.
- **Stop checks scoped to the files the stopping agent wrote** (user decision). A PostToolUse hook records each written path per (session, caller); SubagentStop checks that agent's paths, Stop the main session's. Known gap, accepted: files written through Bash (`sed -i`, redirects, heredocs) are not recorded, so they are not checked until the pre-commit commands run. Rejected: the `git diff HEAD` plus untracked list, which blocked an agent on other sessions' and agents' uncommitted work; a `git status` snapshot at agent start, diffed at its stop to catch Bash writes, which picks up parallel sessions' edits as the agent's own; filtering the git-diff list by the `scope.py` allow-lists, which still blocks on other agents' in-scope dirty files.
- **Hook tests drive each hook as a subprocess with a JSON payload on stdin**, in a throwaway git repo (plus a worktree and a scratch repo) and with `TMPDIR` set to a pytest tmp dir. That is the interface Claude Code uses, so the tests cover the `__main__` exit code, the single stdout object and the `functools.cache`d payload, and never depend on the real checkout's dirty state or the real `/tmp` records. Rejected: importing the hooks, which would need `.claude/hooks` on `sys.path` and resetting the cached payload and tree per test. The ownership-map tests are the exception: they import `scope.py` for its pure `load_map` and `covers` only, so the check uses the hook's own matching. The `lint.py` and `typecheck.py` checks are left untested because they shell out to the uv tools (slow, and they need a project environment in the temp repo); only their `stop_hook_active` exit is tested.
